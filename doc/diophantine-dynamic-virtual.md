# Диофантовы уравнения, динамика из статики, виртуальное дерево

## Диофантовы уравнения

`diophantine(a,b,c)` описывает все целые решения `a*x+b*y=c`. Это именно линейное уравнение с двумя неизвестными, не произвольное полиномиальное диофантово уравнение.

- `bounds(lx,rx,ly,ry)` пересекает текущую область с включительными границами. `nullopt` означает отсутствие соответствующей границы. Для неотрицательных решений: `bounds(0,nullopt,0,nullopt)`.
- `count()` возвращает `optional<i128>`: 0 — решений нет, положительное значение — точное число, `nullopt` — бесконечно много. Проверяйте именно `count()==optional<i128>(0)` для отсутствия решений; `!count()` означает бесконечность!
- `minimum(p,q)` минимизирует `p*x+q*y`. Статусы: -1 — решений нет, 0 — функция не ограничена снизу, 1 — найденные координаты `x,y`.
- `minimum(0,0)` выдаёт произвольное допустимое решение. Для максимума использовать `minimum(-p,-q)`. Для минимума суммы — `minimum(1,1)`.
- Объект можно копировать перед добавлением другой системы ограничений. Поля `x0,y0,dx,dy` задают все решения линии, а `t` — допустимый целочисленный интервал параметра. Для `a=b=c=0` множество решений — плоскость, не линия.

Коэффициенты, границы и веса цели по модулю не более 10^18. Внутри используется `__int128`: он нужен для коэффициентов Безу после масштабирования, вычисления границ и количества решений. Не приводите ответы к `long long` без проверки. Даже при корректных координатах прямое вычисление `a*x+b*y` или `p*x+q*y` для неограниченной задачи может переполнить `__int128` из-за больших взаимно сокращающихся слагаемых; сам решатель этих произведений не вычисляет. Если нужно значение цели для огромных координат, используйте длинную арифметику.

Полный пример включён в печатный раздел. `floor_div` и `ceil_div` корректны для обоих знаков знаменателя; знаменатель должен быть ненулевым. Функции рассчитаны на описанные пределы задачи, а не на `INT128_MIN / -1`.

## Динамика из статической структуры

Метод двоичного счётчика применим, когда ответ по объединению непересекающихся наборов можно получить из ответов по отдельным наборам: сумма, минимум, максимум, логическое «или» и т.п. Храним не более одного блока каждого размера 1,2,4,...; при добавлении объединяем занятые блоки как переносы в двоичной записи числа элементов. Каждый элемент участвует не более чем в O(log N) перестроениях. Если статическое построение линейное по размеру данных, суммарная стоимость — O(общий размер * log N); запрос обращается к O(log N) блокам. Для нелинейной стоимости построения нужно отдельно просуммировать стоимости по уровням — обещать просто логарифмический множитель на каждую операцию нельзя.

`dynamic_suffix_automaton` хранит мультимножество строк и считает суммарные вхождения непустого образца с перекрытиями. Это не поиск в общей конкатенации строк и не число документов, содержащих образец. В каждом блоке строки разделены символом `{`, отсутствующим в запросах. Существующий суффиксный автомат расширен до 27 символов; число вхождений распространяется по ссылкам в порядке длин за линейное время. Образец из `a..z` не пересечёт разделитель.

Размеры блоков измеряются в количестве добавленных строк. За N вставок общей длины L время O((L+N)log(N+1)), память O(L+N), запрос O(|p|log(N+1)). Одна вставка может быть линейной по всей накопленной длине, даже если вставляемая строка короткая. Число состояний и длины в базовом автомате имеют тип int; данные должны помещаться в эти индексы и в память (каждое состояние хранит 27 переходов).

Удаление одного существующего экземпляра можно реализовать вторым таким набором и разностью ответов. За корректностью удалений следит вызывающий код: для каждой строки удалений должно быть не больше вставок. Память зависит от всей истории, а не только от живых строк; для длительной работы можно периодически перестраивать структуру из текущих элементов. Вычитание работает для счётчиков, но не переносится автоматически на минимум/максимум.

Источник метода: Bentley–Saxe; [конспект Jeff Erickson](https://jeffe.cs.illinois.edu/teaching/datastructures/2011/notes/01-statictodynamic.pdf).

## Виртуальное дерево

Допустим, исходное дерево содержит пути `0–1–2` и `1–3–4`, а интересуют только S={2,4}. Их общий предок — 1. Виртуальное дерево содержит исходные вершины {1,2,4}; ребро 1→4 заменяет путь 1→3→4. Неотмеченная вершина 3 исчезла, поскольку на этом пути она не является нужной точкой ветвления; вершина 0 тоже не нужна.

`compressTree(lca,{2,4})` возвращает пары `(parent_index, original_vertex)`. При таком порядке DFS это `{(0,1),(0,2),(0,4)}`. Число 0 в первых компонентах — индекс в возвращённом массиве, а не номер исходной вершины. Родитель корня условно он сам; корень имеет исходный номер 1.

Чтобы восстановить списки детей, для каждого i>0 добавить i в `children[ret[i].first]`. Вес сжатого ребра — разность глубин его концов; при весах рёбер используйте расстояния от исходного корня. Родитель всегда раньше потомка, поэтому ДП снизу вверх удобно делать обратным проходом по ret.

Пример: сумма расстояний между всеми неупорядоченными парами различных отмеченных вершин. Пусть k=|S| без повторов, cnt[i] — число отмеченных вершин в виртуальном поддереве i. Тогда вклад ребра к родителю равен `weight * cnt[i] * (k-cnt[i])`. Суммируем вклад и прибавляем cnt[i] к cnt[parent]. В исходном дереве могут быть миллионы вершин, но после предобработки LCA обрабатываем O(k) виртуальных вершин.

Для построения сортируем S по времени входа DFS, добавляем LCA соседних элементов, снова сортируем и убираем повторы. Получается не более 2k−1 вершин. Пустой вход возвращает пустой вектор. При выборе S с повторениями кратности для конкретной задачи нужно хранить отдельно: структура дерева содержит каждую вершину один раз.
