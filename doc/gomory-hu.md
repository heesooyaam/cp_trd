# Дерево Гомори — Ху

Нужно, когда для одного **неориентированного** графа с неотрицательными
ёмкостями надо отвечать на много запросов максимального потока между разными
вершинами. Для единственного запроса достаточно Диница.

```cpp
vector<flow_edge> edges = {{0, 1, 8}, {1, 2, 3}, {2, 3, 6}};
auto tree = gomory_hu(4, edges);
vector<vector<pair<int, ll>>> graph(4);
for (auto [u, v, cap] : tree) {
    graph[u].eb(int(v), cap);
    graph[v].eb(int(u), cap);
}
```

Каждое неориентированное ребро передаётся один раз. Кратные рёбра допустимы.
Вершины нумеруются от 0, ёмкости и ответ имеют тип `ll`; суммы ёмкостей
не должны переполняться. Несвязный граф допустим: дерево содержит нулевые рёбра.
Для 0 или 1 вершины возвращается пустое дерево.

Ответ для `u != v` — **минимальная ёмкость ребра на единственном пути между ними
в дереве**. В примере для 0 и 3 это `min(8, 3, 6) = 3`.
Можно находить путь DFS/BFS за O(n) на запрос либо подготовить двоичные подъёмы
с минимумом по каждому прыжку: O(n log n) подготовки и O(log n) на запрос.
Для пары из разных компонент исходного графа ответ 0.

Построение делает n−1 запусков нашего `dinic` из `TeamDinic.h`.
Неориентированное ребро представляется двумя направленными с одинаковой ёмкостью.
После `max_flow` последний неуспешный BFS отмечает все вершины стороны истока:
`level[v] != -1`. Именно этот разрез нужен для обновления родителей дерева.

Проверка: для случайных графов сравнивается ответ каждой пары с независимой
реализацией потока; отдельные случаи покрывают несвязность и большие ёмкости.
