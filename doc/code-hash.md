# Проверка перепечатанного кода

Справа над C++-листингом в PDF стоят шесть шестнадцатеричных символов,
например `d47dc3` у `RomanNumerals.h`. Это контрольная сумма напечатанного
фрагмента: она помогает найти случайные изменения при перепечатывании.
Это не строковый хешер для решения задач и не проверка правильности алгоритма.

## Запуск

На контесте сохранить напечатанный скрипт в `hash.sh`. Перепечатать выбранный
листинг в отдельный `snippet.cpp`, сохранив имена, константы и все строки кода.
Скрипт и фрагмент могут лежать рядом:

```sh
sh hash.sh < snippet.cpp
```

Скрипт читает стандартный ввод: знак `<` направляет в него содержимое файла.
Права на исполнение не нужны, потому что скрипт запускает `sh`.
Если скрипт взят из клона этого репозитория, команда из корня репозитория:

```sh
sh content/contest/hash.sh < snippet.cpp
```

Если шаблон уже внутри решения, выделить **ровно его строки**. Например,
если весь листинг занимает строки 20–70 включительно:

```sh
sed -n '20,70p' solution.cpp | sh hash.sh
```

Перед сверкой полезно выполнить `sed -n '20,70p' solution.cpp` без конвейера
и посмотреть, что попало в диапазон. Номера здесь иллюстративные: заменить
их фактическими границами своего фрагмента.

Для неизменённого напечатанного `RomanNumerals.h` результат:

```text
d47dc3
```

Он должен совпасть с кодом над этим листингом в PDF. Сначала сверить копию,
затем менять имена, типы, константы и выбирать нужные варианты реализации.
После адаптации совпадение с исходным PDF уже не ожидается.

## Что именно включать

- Весь код одного листинга, от первой до последней напечатанной строки.
- Все напечатанные внутри него `#define`, примеры и вспомогательные функции.
- Не включать заголовок, описание, сложность, шестизначный хеш и число строк.
- Не добавлять общий шаблон решения: `main`, `using namespace std`, общие
  `include` и макросы. Если строка напечатана непосредственно **внутри самого
  листинга**, её, напротив, нужно оставить.
- Не дописывать зависимости, указанные слева над листингом: они хешируются
  отдельно. Сборщик PDF обычно убирает `#include` и `#pragma once` из исходного
  заголовка. Поэтому запуск скрипта на полном `.h` из репозитория не обязан
  совпадать с PDF.

Сборщик также обрабатывает служебные пометки `include-line`, `exclude-line`
и `///`. Ориентир для сверки — **то, что напечатано в PDF**, а не исходный
заголовок до обработки. Если в листинге показаны альтернативы, сначала
перепечатать и сверить все строки, затем оставить нужную альтернативу.

## Что делает скрипт

1. GNU `cpp -dD -P -fpreprocessed` удаляет комментарии. В этом режиме макросы
   не раскрываются, `include` не подключают файлы; `-dD` сохраняет определения
   макросов, `-P` убирает маркеры исходных строк.
2. `tr -d '[:space:]'` удаляет пробельные символы.
3. `md5sum` (Linux) либо `md5 -q` (macOS) считает MD5, `cut -c-6` оставляет
   первые шесть символов.

Описание режимов препроцессора:
[документация GCC](https://gcc.gnu.org/onlinedocs/gcc/Preprocessor-Options.html).

На macOS нужен GNU cpp: `brew install gcc`. Скрипт ищет `cpp-16`, `cpp-15`,
`cpp-14`, `cpp-13`; если установлен другой номер, добавить его в список.
На Linux обычно достаточно доступного в PATH GNU `cpp`.

## Если хеши различаются или совпали подозрительно

При различии сначала проверить диапазон строк, лишние `include`/`main`,
пропущенные примеры, отличающиеся имена и константы. Затем искать опечатку
в коде. При сообщениях об ошибках от `cpp` сначала устранить их: текущий
скрипт — конвейер `sh`, и успешный выход последней команды не гарантирует,
что препроцессор успешно отработал.

Совпадение не доказывает эквивалентность или корректность:

- Хеш сокращён до 24 бит, коллизии возможны.
- Пробелы удаляются **даже внутри литералов**: `"a b"` и `"ab"` дадут
  одинаковый результат, хотя строки различаются.
- Разные границы токенов тоже могут исчезнуть: не стоит считать это
  полноценным сравнением синтаксических деревьев C++.
- Не проверяются зависимости вне фрагмента и правильность вызова шаблона
  из решения. Например, корректно перепечатанное дерево не обнаружит
  ошибку `rem`, случайно вызывающего `add` в вашей обёртке.

После сверки всё равно нужны компиляция, простые и граничные тесты,
а для собственной логики — сравнение с перебором.
