# Деревья отрезков

В справочнике печатаются `GenericSegmentTree.h`, `SegmentTreeExample.h`, `PersistentSegmentTree.h` и `PersistentVersions.h`. Старые обычное и lazy-ДО остаются только в архиве исходников для upstream-тестов; HLD использует новый универсальный шаблон.

## Универсальное ДО

Все интервалы полуоткрытые `[l,r)`. `update(pos,tag)` и `update(l,r,tag)` применяют одну и ту же операцию; точечный метод вызывает отрезковый и пересчитывает предков. `get(pos)` возвращает узел одного элемента, `get(l,r)` — агрегат. Пустой запрос возвращает `neutral_node()`.

Параметры:

- `node_t`: агрегат отрезка; `node_t{}` — значение одного начального листа.
- `combine(left,right)`: ассоциативное объединение в порядке слева направо; коммутативность не обязательна.
- `neutral_node()`: нейтральный элемент combine, то есть пустой отрезок.
- `push_t`: отложенное обновление.
- `composition(old,new)`: выполнить old, затем new; порядок важен.
- `sync(node,tag)`: применить tag ко всему отрезку; храните длину внутри узла, если она нужна.
- `neutral_push()`: тождественное обновление.

Нужны законы `sync(sync(x,old),new) == sync(x,composition(old,new))` и согласованность sync с объединением соседних непустых отрезков. Функции лучше поместить в namespace: глобальное имя `sync` занято также POSIX-функцией.

Пример сложения и суммы напечатан полностью. Для присваивания и прибавления удобно хранить аффинный тег `x -> mul*x + add`:

```cpp
struct tag_t { ll mul = 1, add = 0; };
tag_t composition(tag_t old_p, tag_t new_p) {
    return {new_p.mul * old_p.mul,
            new_p.mul * old_p.add + new_p.add};
}
node_t sync(node_t x, tag_t f) {
    return {f.mul * x.sum + f.add * x.len, x.len};
}
tag_t neutral_push() { return {1, 0}; }
// update(l,r,{1,d}) — прибавить d;
// update(l,r,{0,v}) — присвоить v.
```

## Персистентное ДО

`SumTree<T>` присваивает значение, не прибавляет. `update(pos,val,root)` возвращает индекс корня новой версии. `get_sum(l,r,root)` возвращает T, поэтому для больших сумм используйте `SumTree<ll>`.

Корень 0 означает полностью нулевой массив. Можно ветвиться от любого сохранённого корня. Размер дерева положительный; пустой запрос суммы допустим.

В примере пользователя удалено второе одинаковое `update(i,1,last_version)`: оно не меняло ответ, но расходовало дополнительные узлы. После каждой позиции сохраняется окончательный корень, когда лишнее старое вхождение уже обнулено. Запрос `[l,r)` использует `roots[r-1]`. Ответ — сумма `min(k,count[x])`, а не обязательно количество различных элементов (это оно только при k=1).
