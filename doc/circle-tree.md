# Дерево вложенности окружностей

Исходная идея и сканирующая прямая — из heesooyaam/AlgoTemplates, Other/circles_to_tree_scanline.cpp. Убраны ввод-вывод и DP конкретной задачи; осталась структура circle_tree.

~~~cpp
vector<circle_tree::circle> circles{
    {0, 0, 10}, {0, 0, 3}, {30, 0, 2}
};
circle_tree tree(circles);
// parent = {-1, 0, -1}
// roots = {0, 2}; children[0] = {1}
~~~

Индексы исходного вектора сохраняются. parent[v] — ближайшая содержащая окружность; -1 обозначает внешний корень. children — направленные рёбра от родителя к ребёнку. Если нужен один корень, добавьте виртуальную вершину n и соедините её с roots.

**Условия:** радиусы положительные; границы попарно не пересекаются, не касаются и не совпадают. Круги могут быть строго вложены друг в друга или находиться снаружи. Это именно лес вложенности, не граф пересечений. Входные условия не проверяются квадратично.

Вертикальная прямая движется слева направо. Для окружности есть события x-r (появление) и x+r (исчезновение). Пока она активна, храним нижнюю и верхнюю дугу в set, упорядоченные по высоте пересечения с прямой.

При появлении окружности ищем ближайшую дугу выше её левой крайней точки:

- Это верхняя дуга окружности j — новая окружность находится внутри j, значит parent=j.
- Это нижняя дуга j — новая окружность находится снаружи j, в той же области вложенности: parent=parent[j].
- Дуг выше нет — новая окружность внешняя.

Почему можно менять scan_x в компараторе set: относительный порядок **уже активных** дуг не меняется, поскольку границы не пересекаются. Нижняя и верхняя дуги одной окружности всегда упорядочены явно, включая её крайние точки. Если допустить пересечения или касания, это рассуждение перестаёт работать. Исчезающие дуги удаляются по сохранённым итераторам.

События с одинаковым x сначала удаляют закончившиеся окружности, затем добавляют новые. Для входов с непересекающимися границами это допустимо: касание на этой вертикали запрещено.

Геометрические вычисления — long double. Формула (r-dx)*(r+dx) уменьшает потерю точности около крайней точки; max(0, ...) защищает sqrt от небольшого отрицательного округления. Это не точный геометрический предикат: почти касающиеся окружности при огромных координатах требуют особого анализа точности. Не добавляйте epsilon в компаратор set — он может нарушить транзитивность. Не используйте fast-math для этой структуры.

Время O(n log n), память O(n). Пустой ввод поддерживается. Конструктор не использует рекурсивный обход, поэтому длинная цепочка вложенности не расходует стек.
