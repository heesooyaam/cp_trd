# Что такое стресс-скрипт

Нужно решить задачу: найти максимум непустого массива. Есть три программы:

- `gen.cpp` по номеру `seed` генерирует маленький случайный массив.
  Тот же seed даёт тот же тест при повторном запуске этого генератора.
- `brute.cpp` решает задачу простым способом: сортирует массив и берёт
  последний элемент. Здесь это эталон; в сложной задаче можно перебирать
  все подмножества, перестановки или все последовательности операций.
- `solution.cpp` — проверяемое решение. В примере **специально есть ошибка**:
  максимум начинается с нуля, поэтому ответ неверен, если все числа отрицательные.

`stress.sh` запускает все три программы на одном тесте, сравнивает ответы,
затем повторяет с новым seed. При первом расхождении останавливается и
оставляет `input.txt`, `expected.txt` и `actual.txt`.

## Попробовать

Из корня репозитория:

```sh
cd doc/stress-demo
g++ -std=c++20 -O2 gen.cpp -o gen
g++ -std=c++20 -O2 brute.cpp -o brute
g++ -std=c++20 -O2 solution.cpp -o solution
sh stress.sh 1000
```

На macOS вместо `g++` использовать установленный GNU C++, например
`g++-16`. Программы читают stdin и пишут stdout, без `freopen`.
Генератор создаёт 1..8 чисел из [-10,10]; в этой задаче такой маленький
тест уже позволяет обнаружить ошибку.

Разобрать найденное расхождение:

```sh
cat input.txt
cat expected.txt
cat actual.txt
./solution < input.txt
```

Исправить `ans = 0` на `ans = numeric_limits<int>::lowest()`, перекомпилировать
`solution` и снова запустить скрипт. В проверенном запуске ошибка найдена
на seed=2: массив из одного числа -7, эталон отвечает -7, решение — 0.
Повторить этот тест: `./gen 2 > input.txt`. После исправления все 1000
тестов совпали.

## Для своей задачи

Сохранить скрипт, а три C++-программы заменить своими. Эталон должен быть
максимально простым и независимым от основного алгоритма; медленная
сложность допустима, потому что тесты маленькие. В генератор добавить
важные случаи: одинаковые значения, нули, отрицательные числа, крайние
индексы, пустые диапазоны (если разрешены), повторные обновления.

Для дерева отрезков эталоном может быть обычный `vector`: каждое обновление
применяется циклом, сумма отрезка тоже считается циклом. Генератор создаёт
одну последовательность операций для обеих программ. Если `rem` ошибочно
вызывает `add`, ответы на последующие запросы начнут различаться.

`diff -b` игнорирует разное количество пробелов между токенами, но учитывает
разбивку на строки. Здесь ответ
единственный и целочисленный. Для вещественных ответов нужен свой допуск,
для задач с несколькими допустимыми ответами — проверка корректности,
а не буквальное сравнение.

Это минимальный пример: он не ограничивает время работы процесса. Если
решение зависло, остановить скрипт через Ctrl+C — текущий `input.txt`
останется. При ненулевом коде возврата любой программы `set -e` тоже
останавливает запуск. Отсутствие ошибок на случайных тестах не доказывает
корректность; граничные случаи проверять отдельно.
